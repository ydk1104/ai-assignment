- API 구조

POST /create_document를 만들었어요. 이 환경은 네트워크가 막혀 있어서 npm install과 전체 빌드, 실제 서버 실행은 못 해봤고, 난수 로직(30~100% 경계값, seed 재현성)만 따로 확인했어요. 아래 순서대로 직접 돌려 보시고, 에러가 나면 로그를 보내주세요.

응답(SSE)은 지금까지 보낸 누적 토큰 수를 약 10번에 나눠 보내고, 마지막에 done 이벤트로 끝나요.

```
data: {"tokens":78}
data: {"tokens":156}
...
event: done
data: {"tokens":780}
```

헤더가 없거나 값이 잘못되면 400이에요. 같은 Idempotency-Key로 다른 body를 보내면 422예요.

- DB 구조

token_ledger는 원장이에요. 요청 한 건당 한 줄이 쌓이고(user_id, idempotency_key, 토큰 수, 시각 등) 수정이나 삭제는 하지 않아요.  
user_token_totals는 유저별 합계예요.  
두 테이블은 한 트랜잭션에서 같이 갱신돼요. 같은 userId와 Idempotency-Key가 다시 오면 DB에 다시 쌓지 않고, 저장된 토큰 수로 같은 스트림을 다시 보내줘요. 이때 응답 헤더에 Idempotent-Replayed: true가 붙어요.  
테이블은 서버 시작 시 자동 생성돼요. API 2대가 동시에 떠도 충돌하지 않게 락을 걸었어요.

- 추신
